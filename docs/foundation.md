# Application foundation

Fold has persistent PostgreSQL data and Better Auth email/password sessions.
Each owner has one private workspace; server-side queries scope forms and
responses to that owner. Anonymous visitors can only read/submit published forms.
The public `/api/health` route is database-free.

Use the [development guide](development.md) for local setup and
[testing guide](testing.md) for isolated verification. The canonical publishing
recipe is `.neander/compose.yaml`; it requires the deployment database URL,
public origin and generated authentication secret. Local PostgreSQL is an opt-in
Compose service and is separate from managed Neon provisioning.

Auth tables were generated by the pinned Better Auth CLI and exported from
`server/schema.ts`. Drizzle SQL/metadata in `drizzle/` are versioned together.
Apply migrations before runtime checks; never migrate during build/startup,
reset an existing database, or use `auth migrate` with the Drizzle adapter.
The `.neander/check-auth.mjs` script verifies migrated runtime session behavior;
it does not create schemas.

The [builder guide](builder.md) describes the current form model and lifecycle.
Legacy one-question forms remain readable alongside multi-block forms; responses
retain historical schema snapshots. Optional [password recovery](password-recovery.md)
uses the existing authentication tables and a deployment-owned email provider.
